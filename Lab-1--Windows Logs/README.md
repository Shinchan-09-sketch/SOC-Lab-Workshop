# Lab 1: Windows Event Log Collection

## Aim

Configure, monitor, and analyze Windows Event Logs using Splunk Enterprise running on the Windows host.

In this lab, students will investigate Windows Security Events, understand Event ID 4624 and different logon types, and perform a basic SOC investigation using Splunk.


---

## Step 1: Verify Splunk Enterprise

Before configuring Windows Event Log collection, ensure that Splunk Enterprise is running on the Windows host.

Open a web browser and navigate to:

```text
http://localhost:8000
```

Alternatively, use the host IP:

```text
http://192.168.184.1:8000
```

Log in using the Splunk Enterprise administrator credentials created during installation.

---

## Step 2: Configure Windows Event Log Collection

In Splunk Enterprise, navigate to:

**Settings → Data Inputs → Local Event Logs**

Click **New**.

Select the Windows Event Logs required for the lab:

- Security
- System
- Application

The **Security** log is the primary source used in this exercise.

Set the destination index to:

```text
main
```

Save the configuration.

---

## Step 3: Verify Windows Events in Splunk

Open:

**Search & Reporting**

Run:

```text
index=main sourcetype="WinEventLog:Security"
```

If the configuration is successful, Windows Security Events should appear in the search results.

You can also search:

```text
sourcetype="WinEventLog:Security"
```

Verify that events are being indexed successfully.

---

## Step 4: Open Windows Event Viewer

On the Windows host, press:

```text
Win + R
```

Enter:

```text
eventvwr.msc
```

Press **Enter**.

Navigate to:

**Windows Logs → Security**

The Security log contains authentication and other security-related events generated by Windows.

---

## Step 5: Find Event ID 4624

Inside:

**Windows Logs → Security**

Find an event with:

```text
Event ID: 4624
```

Event ID **4624** indicates that a logon session was successfully created.

A successful logon does **not automatically mean that an attack occurred**.

The SOC analyst must examine the event details and surrounding activity before deciding whether the activity is legitimate or suspicious.

---

## Step 6: Understand Logon Types

Open an Event ID 4624 event and locate the **Logon Type** field.

Common logon types include:

| Logon Type | Description |
|---|---|
| 2 | Interactive |
| 3 | Network |
| 4 | Batch |
| 5 | Service |
| 10 | Remote Interactive / RDP |

### Logon Type 2 — Interactive

A user logged on directly to the computer.

### Logon Type 3 — Network

A user or system accessed the computer through the network.

### Logon Type 4 — Batch

A process or scheduled task performed a batch logon.

### Logon Type 5 — Service

A Windows service logged on.

### Logon Type 10 — Remote Interactive

A user logged on remotely, commonly through Remote Desktop Protocol (RDP).

---

## Step 7: Analyze an Example Event

An example Event ID 4624 observed during the lab may contain:

```text
Event ID: 4624
Account: SYSTEM
Logon Type: 5
Process: services.exe
```

This can represent normal Windows service activity.

Therefore, the presence of Event ID 4624 alone should not be treated as an attack.

Examine the following information:

- Account
- Logon Type
- Source Network Address
- Authentication Package
- Process Information
- Computer Name
- Time of the event

---

## Step 8: Search for Event ID 4624 in Splunk

Return to:

**Splunk Enterprise → Search & Reporting**

Run:

```text
index=main sourcetype="WinEventLog:Security" EventCode=4624
```

This search displays successful Windows logon events.

Review the returned events and examine fields such as:

- Account Name
- Logon Type
- Source Network Address
- Authentication Package
- Process Information
- Computer Name
- Event Code

---

## Step 9: Investigate Successful Logons

Use the following search:

```text
index=main sourcetype="WinEventLog:Security" EventCode=4624
```

Look for activity that may require further investigation.

Examples include:

- Unexpected user accounts
- Unexpected source IP addresses
- Remote Interactive / RDP logons
- Unusual logon times
- Repeated logons from unfamiliar systems
- Unexpected service activity

Do not classify an event as malicious based on a single field.

Always investigate the context.

---

## Step 10: Compare Event Viewer and Splunk

Select a Windows Security Event from:

**Windows Logs → Security**

Identify information such as:

```text
Event ID
Account
Logon Type
Time
Source Information
```

Then search for the corresponding event in Splunk.

For example:

```text
index=main sourcetype="WinEventLog:Security" EventCode=4624
```

Compare the information shown in Event Viewer with the information indexed by Splunk.

This demonstrates how the same security event can be viewed from both the operating system and the centralized SOC platform.

---

## Step 11: Perform a Basic SOC Investigation

Use the collected information to answer the following questions:

1. What account generated the event?
2. What was the Logon Type?
3. Was the logon local or remote?
4. What was the source address?
5. What process was involved?
6. Was the activity expected?
7. Is additional investigation required?

The investigation process is:

```text
Event
  ↓
Analysis
  ↓
Context
  ↓
Investigation
  ↓
Decision
```

An event becomes meaningful only when its context is understood.

## Step 12: Verify the Final Splunk Search

Run the following search:

```text
index=main sourcetype="WinEventLog:Security"
```

Then specifically search for successful logons:

```text
index=main sourcetype="WinEventLog:Security" EventCode=4624
```

Verify that the expected Windows Security Events are displayed.

## Result

Successfully configured Splunk Enterprise to collect local Windows Security Events and analyzed Event ID `4624` using Splunk.

The lab demonstrates how a SOC analyst can investigate authentication activity, understand different Windows logon types, and distinguish normal system behavior from potentially suspicious activity.

---

## Key Takeaways

- Windows Event Viewer provides detailed Windows Security Events.
- Splunk Enterprise can directly collect local Windows Event Logs.
- Event ID `4624` represents a successful logon session.
- Event ID `4624` does not automatically indicate an attack.
- Logon Type provides important context during authentication investigations.
- Logon Type `5` commonly represents a service logon.
- Logon Type `10` commonly represents Remote Desktop / RDP activity.
- SOC analysts should investigate context rather than judging an event in isolation.
- Splunk can centralize and search Windows Security Events for investigation.

---

## SOC Investigation Lesson

> A SOC analyst does not look at one event and immediately call it an attack. The analyst collects evidence, examines the context, correlates relevant information, and then decides whether the activity is legitimate or suspicious.
